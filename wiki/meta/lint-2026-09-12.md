## 5. 🔴 모순 1건 — 비대칭 표시 + **위키 내부에 해소 근거가 이미 있음**

### 5.1 현 상태

`multi-agent-systems.md:83`에 마커가 있다:

> ⚠️ **Contradiction (2026-09-11):** 코딩 도메인에서의 멀티에이전트 적합성
> - [[2025-06-13-multi-agent-research-system]] (2025-06): 코딩은 **부적합** — *"most coding tasks involve fewer truly parallelizable tasks than research, and LLM agents are not yet great at coordinating and delegating to other agents in real time."*
> - [[ai-native-sdlc]] (2026-08): worktree 병렬 세션 2~3개 + 에이전트 리뷰 pass를 권장

**문제 1 — 비대칭.** 마커가 `ai-native-sdlc`를 지목하는데 그 페이지에는 대응 마커가 없다. `ai-native-sdlc`만 읽는 사람은 반대 증거가 위키에 있다는 사실 자체를 모른다.

### 5.2 🎯 **새 발견: 해소 근거가 이미 `claude-code.md`에 있다**

기록된 해소 가설 ①("오케스트레이터가 사람이냐 에이전트냐")은 **추가 조사가 필요 없다.** `claude-code.md`가 이미 명시적으로 답하고 있다:

> **`claude-code.md` → 병렬성 → Parallel sessions (worktrees):**
> "병렬 세션은 각자의 git worktree에서 별도 작업을 하는 완전한 Claude Code 인스턴스다. **서로를 모르며, 공유하는 것은 그것들을 조종하는 엔지니어뿐이다.**"
>
> **같은 페이지 → Subagents:**
> "**단일 세션 안에서** 자기 컨텍스트 윈도와 도구 제한을 갖고 도는 스코프된 헬퍼."
>
> **같은 페이지 → 병렬 세션 vs subagent:**
> "병렬 세션은 엔지니어가 동시에 진행할 수 있는 작업 수를 늘리고, subagent는 각 세션이 자기 작업에 집중하게 유지한다. **엔지니어의 일은 그 전부를 조종하고 리뷰하는 것.**"

2025-06 소스가 부정한 것은 *"LLM agents ... coordinating and delegating **to other agents in real time**"* — 즉 **에이전트가 에이전트에게 실시간 위임하는 것**이다. SDLC 플레이북이 권하는 병렬은 그것이 아니다. 세션끼리 서로를 모르고, 조정 주체는 사람이며, 천장도 *"한 사람이 제대로 리뷰할 수 있는 스트림 수"*로 사람에게 묶여 있다.

**결론: 두 소스는 서로 다른 대상을 말하고 있으며, 실질적 모순이 아니다.** 남는 것은 정도의 차이(2025-06의 "not yet"이 14개월 뒤 얼마나 완화됐는가)뿐이다.

**권장:** 마커를 삭제하지 말고 **"해소됨(resolved)"으로 갱신**하고 근거를 `[[claude-code]]`로 인용한다. 그리고 `ai-native-sdlc`에 한 줄짜리 대칭 포인터를 단다. 이 해소는 **사용자 확인이 필요하다** — 위 독해에 동의하시는지.

### 5.3 남는 진짜 질문 (모순은 아니나 미해결)

두 소스 모두 **에이전트가 에이전트에게 위임하는 코딩**에 대해서는 데이터를 주지 않는다. 2025-06은 "아직 안 된다"고 했고, 2026-08은 그 구성을 아예 다루지 않는다. → §8 데이터 갭
