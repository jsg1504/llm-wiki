# MetaGPT: Meta Programming for a Multi-Agent Collaborative Framework

> 인간 소프트웨어 회사의 SOP(Standard Operating Procedures)를 프롬프트 시퀀스로 인코딩해 LLM 멀티에이전트 협업의 cascading hallucination을 줄이는 프레임워크. HumanEval 85.9% / MBPP 87.7% Pass@1로 당시 SoTA.

## Context

- **저자**: Sirui Hong (DeepWisdom, 1저자), Chenglin Wu (DeepWisdom CEO, MetaGPT 창시자), Jürgen Schmidhuber (KAUST AI Initiative · IDSIA, 자문) 등 다수.
- **발표**: ICLR 2024.
- **배경**: 2023년 AutoGPT/LangChain/AgentVerse/ChatDev 등 LLM 기반 자율 에이전트 시스템이 쏟아져 나왔지만, 단순 작업은 풀어도 복잡한 작업에서는 logic inconsistency와 cascading hallucination으로 무너지는 한계가 있었다. MetaGPT는 이 문제를 "에이전트 간 자유 대화"가 아니라 "인간 조직의 표준 절차(SOP)"를 도입해 풀자고 제안한다.
- **코드/공개**: github.com/geekan/MetaGPT. 본 논문은 v7로, 2024년 11월에 갱신된 최신 버전.

## Key Claims

1. **SOP를 프롬프트 시퀀스로 인코딩한다.** 인간 소프트웨어 회사의 표준 절차(요구사항 분석 → 시스템 설계 → 태스크 분해 → 코딩 → QA)를 그대로 에이전트 워크플로우에 매핑한다. 이것이 "어셈블리 라인" 패러다임을 가능하게 하고 역할 간 모호함과 잡담을 줄인다 (저자들은 "Hi, hello and how are you?" 같은 idle chatter를 명시적 안티패턴으로 든다).

2. **5개 역할 전문화.** Product Manager, Architect, Project Manager, Engineer, QA Engineer. 각 역할은 name·profile·goal·constraint·tool로 정의된다 (예: Engineer는 "PEP8 준수, modular, readable" 제약). Ablation에서 역할이 1→4로 늘 때 executability가 1.0→4.0, human revision cost가 10→2.5로 단조 개선됨 (Table 3).

3. **Structured Communication Interfaces — 자연어 대화 대신 문서/다이어그램으로 핸드오버.** Architect는 system interface design + sequence flow diagram을 산출한다. ChatDev처럼 dialogue로 주고받지 않고 PRD/시스템 설계 같은 구조화된 산출물 자체가 통신 매개체. 저자들은 자연어만으로는 "telephone game (Chinese whispers)" 왜곡이 누적된다고 주장.

4. **Publish-Subscribe + Shared Message Pool.** 모든 에이전트는 글로벌 메시지 풀에 publish하고, role profile 기반으로 필요한 메시지에만 subscribe. one-to-one 통신의 토폴로지 폭증과 정보 과부하를 해결.

5. **Executable Feedback Loop = 코드 품질의 핵심 차별화 포인트.** Engineer가 코드 → 단위 테스트 작성 → 실행 → 실패 시 디버그를 최대 3회 retry. 이 메커니즘만으로 HumanEval +4.2%, MBPP +5.4% (Pass@1) 개선. SoftwareDev 벤치에서 executability 3.67→3.75, human revision cost 2.25→0.83으로 떨어짐.

6. **벤치마크 결과 (당시 SoTA).**
   - HumanEval Pass@1: **85.9%** (GPT-4 single-shot 67.0% 대비)
   - MBPP Pass@1: **87.7%**
   - SoftwareDev (자체 70-task 벤치): executability 3.75/4, ChatDev(2.25) 대비 큰 격차. 단 token usage는 ChatDev 19,292 → MetaGPT 31,255로 더 비쌈.

> ⚠️ **Contradiction (2026-04-28):** [[2307.07924-chatdev]] 논문은 **자체 SRDD 벤치(1,200 task)에서 ChatDev Executability 0.8800 > MetaGPT 0.4145** 로 정반대 결과를 보고한다. 즉 두 논문이 자기 자체 벤치에서 서로를 이긴다고 주장. HumanEval/MBPP(third-party 벤치) 결과는 본 논문의 주장이 그대로 유지되지만, MetaGPT vs ChatDev의 직접 비교에는 자체 벤치 cross-citation을 신뢰하기 어렵다. 등록: [[contradictions]].

## Architecture (요약)

```
요구사항(Boss) 
  → Product Manager      WritePRD          → PRD 문서
  → Architect            WriteDesign       → 시스템 설계 + sequence diagram
  → Project Manager      WriteTasks        → 태스크/파일 리스트
  → Engineer             WriteCode         → 코드 + 단위 테스트 (반복)
  → QA Engineer          WriteCodeReview   → 리뷰
                         ─────────
            모두 Shared Message Pool에 publish, role 기반 subscribe
```

Engineer는 별도로 **iterative programming loop**: write → execute → feedback → debug, max 3 retries.

## Notable Quotes

> "MetaGPT requires agents to generate structured outputs, such as high-quality requirements documents, design artifacts, flowcharts, and interface specifications." (§1)

## My Notes

- "구조화된 통신 인터페이스"가 단순한 출력 형식 강제가 아니라 **에이전트 간 telephone-game 왜곡**을 명시적 모티베이션으로 둔 점이 인상적. 자연어 대화는 LLM 사이에서도 lossy하다는 관찰.
- Token cost는 ChatDev 대비 1.6배. SOP의 풍부함은 공짜가 아님.
- Ablation Table 3은 단순하지만 강력한 evidence — 역할 추가 = monotonic improvement. 다만 모든 task domain에 일반화될지는 별개 문제.
- Executable feedback (3 retry)은 사실상 하나의 작은 self-correction loop이고, 이것 자체가 최근 유행한 reflexion/critic 패턴과 친척 관계.
- Schmidhuber가 자문으로 들어온 게 흥미로움 — 그의 "learning to learn" 계보를 "programming to program"으로 명시적으로 잇는 의도가 본문에 있음.
