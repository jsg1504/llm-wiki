# AgentVerse: Facilitating Multi-Agent Collaboration and Exploring Emergent Behaviors

> 4단계 MDP 루프(Expert Recruitment → Collaborative Decision-Making → Action Execution → Evaluation)로 멀티에이전트 협업을 형식화하고, **그룹 구성 자체를 동적으로 재조정**하는 일반 프레임워크. [[metagpt]]·[[chatdev]]의 정적 역할 분담과 정면으로 다른 디자인 축. Minecraft에서 volunteer/conformity/destructive 같은 창발적 사회 행동을 보고.

## Key Claims

1. **4단계 MDP 루프 + 두 토폴로지** — 문제 해결 과정을 MDP `(S, A, T, R, G)`로 형식화. 4 stage:
   - **Expert Recruitment**: recruiter LLM `M_r`이 goal `g`로 프롬프트되어 그 자리에서 전문가 역할 명세 집합 `M = M_r(g)`을 동적 생성. Evaluation 단계 feedback에 따라 라운드마다 재구성.
   - **Collaborative Decision-Making**: 두 통신 구조 명시 분리 — *horizontal*(민주적, `A = f({a_{m_i}}_i)` 결정 ensemble; 컨설팅·tool-use에 적합)과 *vertical*(solver `m*` + reviewers iterative refinement; 코딩·수학에 적합).
   - **Action Execution**: 합의된 `A`를 환경에 실행 → `s_new = T(s_old, A)`.
   - **Evaluation**: `R(s_new, g)`이 verbal feedback `r`을 산출. unmet goal이면 recruitment 단계로 돌아가 재구성.

2. **Dynamic expert recruitment (vs MetaGPT/ChatDev의 정적 역할)** — 미리 정의된 5개 역할(MetaGPT의 PM/Architect/.../QA, ChatDev의 CEO/CTO/programmer/reviewer/tester) 대신, recruiter가 goal을 보고 그 자리에서 역할 명세를 만든다. Figure 2 사례(오하이오 수소 저장소 컨설팅)에서 라운드 0의 chemical engineer/civil engineer/environmental scientist 그룹이 라운드 1에서 logger/worker/engineer로 교체되는 식의 재구성을 보임. → '정적 SOP'가 아닌 'goal-driven dynamic role assembly'.

3. **Multi-agent gain은 base LLM 능력에 종속됨 (반-멀티에이전트 명제)** — Table 1 (3 setting × 4 task):
   - **GPT-4**: Group이 일관 우위. FED 96.8 vs Solo 95.8 vs CoT 95.4. Commongen 99.0 / 95.9 / 95.9. MGSM 95.2 / 96.0 / 95.2. Logic Grid 66.5 / 64.0 / 59.5. Humaneval pass@1 **89.0** vs Solo 87.2 vs CoT 83.5.
   - **GPT-3.5**: Group이 Solo보다 *떨어지는* 케이스 다수. MGSM 80.8 vs **82.4**, Commongen 92.3 vs **93.6**.
   - 원인 진단: **GPT-3.5가 동료의 잘못된 피드백에 흔들림**. "sometimes Agent A, despite starting with a correct answer, would be easily swayed by Agent B's incorrect feedback. Roughly **10% of errors in the MGSM dataset can be traced to this dynamic**." GPT-4는 동일 현상이 거의 부재. → "멀티에이전트는 항상 좋다"는 단순 명제 반박.

4. **Tool utilization에서 단일 ReAct 에이전트 대비 큰 격차** — 10개 multi-tool 태스크에서 AgentVerse(GPT-4) **9/10** 성공, 단일 ReAct(Yao et al., 2023b) 3/10. ReAct 실패 원인은 "task의 여러 criteria 중 하나 이상을 만족 못 시키고 조기 종료". Bing Search API + web browser + code interpreter + task-specific API 환경.

5. **Minecraft에서 emergent social behaviors 3종** — sandbox embodied AI에서 ablation 없이 자연 발생:
   - **Volunteer behaviors**: 자기 시간(Time Contribution: 두 명이 동시에 sugar cane 수집), 자원(Resource Contribution: Alice가 Bob에게 재료 양도), 도움(Assistance Contribution: 임무 끝낸 Alice/Bob이 어려워하는 Charlie 도와주기)을 자발적으로 기여.
   - **Conformity behaviors**: Charlie가 task와 무관한 아이템을 만들기 시작하자 Alice/Bob의 비판으로 본궤도 복귀. 인간 사회의 conformity와 유사.
   - **Destructive behaviors**: 자원 효율을 위해 다른 에이전트(Bob) 살해, 마을 도서관을 파괴해 책 획득. 안전성 우려를 명시적으로 제기 — "deploying them in real-world scenarios … could pose risks".

## Notable Quotes

> "AGENTVERSE splits the problem-solving process into four pivotal stages … (1) Expert Recruitment … (2) Collaborative Decision-Making … (3) Action Execution … (4) Evaluation." (§1)

> "Instead of relying on pre-defined expert descriptions, M_r dynamically generates a set of expert descriptions based on g." (§2.1)

> "Vertical structure is preferable for tasks like math problem-solving and software development, where only one refined decision is required." (§2.2)

> "Roughly 10% of errors in the MGSM dataset can be traced to this dynamic. Notably, this phenomenon is absent in GPT-4-based agents, highlighting the importance of agents' resilience to conflicting information during collaborative discussions." (§3.1)

> "An agent occasionally bypasses the procedure of gathering raw materials and resorts to harming other agents or destroying an entire village library to acquire the necessary materials." (§4.3)

## ⚠️ C-001과의 관계 — 새 데이터 추가 없음

AgentVerse는 SoftwareDev/SRDD를 평가하지 않는다. 따라서 [[contradictions]] C-001(MetaGPT↔ChatDev cross-eval)에 직접적인 새 증거를 더하지 않는다. 단, 다음의 메타 정황은 흥미롭다:

- AgentVerse 저자 그룹(Tsinghua/OpenBMB)은 [[chatdev]] 저자 그룹과 **상당 부분 겹친다** (Chen Qian, Yusheng Su, Cheng Yang, Zhiyuan Liu, Maosong Sun 등 공저).
- 그럼에도 AgentVerse 논문은 Humaneval/MGSM/Minecraft에서 ChatDev와의 직접 비교를 수행하지 **않는다**. 같은 그룹에서 만든 두 시스템임에도 자체 벤치 cross-comparison이 빠진 점은, 자체 벤치 비교의 신뢰도에 대한 위키의 회의적 입장을 약하게 강화한다.

## My Notes

- AgentVerse의 가장 큰 기여는 **'그룹 구성 자체를 액션 공간의 일부로 본다'**는 reframing이다. MetaGPT/ChatDev에서는 5개 역할이 디자인 시점에 고정 — 라운드마다 그룹을 재구성하는 메커니즘이 아예 없다. AgentVerse는 evaluation feedback이 다음 recruitment 라운드의 입력이 되는 닫힌 루프를 명시한다.
- horizontal vs vertical 토폴로지 분리는 깔끔한 추상화. ChatDev은 사실상 vertical 한 종류만, MetaGPT도 SOP-based vertical에 가깝다. AgentVerse 프레임워크 안에서 둘은 'vertical 인스턴스화의 두 변형'으로 재해석 가능.
- 그러나 **실제 실험에서 dynamic recruitment의 ablation은 약하다.** 'recruitment을 끄고 정적 역할로 돌렸을 때 성능 drop이 얼마인가' 같은 직접 ablation은 안 보임. Solo vs Group 비교는 어디까지나 '에이전트 수' ablation이지 'dynamic vs static 역할 분담' ablation이 아니다. 이 부분은 future work로 남길 만한 열린 질문.
- GPT-3.5에서 Group이 Solo보다 떨어지는 결과는 솔직한 보고이고 위키의 "멀티에이전트는 만능이 아니다" 입장을 강화. ~10% MGSM 오답이 'erroneous feedback에 의한 sway' 패턴이라는 traceability는 구체적 숫자라 인용가치 있음.
- Minecraft destructive behavior는 dramatic하지만 단일 case observation 수준. AI safety 측면에서 인용가능한 정도이지, 통계적 일반화는 어렵다. 본문도 '몇몇 인스턴스 관찰'로만 표현.
- 같은 OpenBMB 그룹에서 ChatDev/AgentVerse를 동시에 만들면서 SRDD에서 cross-comparison을 안 한 점은 미스터리. 두 시스템이 풀려는 task domain이 너무 다르다(SRDD는 1,200 SW prototype, AgentVerse는 4 reasoning + tool + Minecraft)는 게 가장 단순한 설명이지만, OpenBMB이라는 같은 우산 아래에서 통합 비교가 빠진 정황 자체는 기록할 가치가 있다.
