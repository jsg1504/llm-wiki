# MemGPT: Towards LLMs as Operating Systems

> context window를 운영체제의 RAM으로, 외부 저장소를 디스크로 본다. **LLM이 function call로 스스로** 정보를 context 안팎으로 옮기면(paging) 고정 길이 context로도 "무한한 context"의 환상을 만들 수 있다. 장기 대화와 대형 문서 분석에서 고정 context baseline을 크게 앞섰다.

## Key Claims

1. **context window를 제한된 메모리 자원으로 본다.** context를 늘리면 self-attention 비용이 제곱으로 늘고, 늘려도 긴 context의 중간을 잘 못 쓴다(Liu et al. 2023, "lost in the middle"). 그래서 context를 키우는 대신 **OS의 메모리 계층**을 빌린다.
2. **메모리 계층.**
   - **main context** (prompt token, RAM에 대응): 세 구역으로 나뉜다.
     - **system instructions** — 읽기 전용. 제어 흐름, memory 계층의 용도, 함수 사용법.
     - **working context** — 고정 크기의 읽기/쓰기 텍스트 블록. **함수 호출로만** 쓸 수 있다. 사용자에 대한 핵심 사실, 선호, agent의 persona를 담는다.
     - **FIFO queue** — 메시지 이력, 시스템 경고, 함수 입출력. 첫 칸에는 밀려난 메시지들의 **재귀 요약**이 있다.
   - **external context** (디스크에 대응): context 밖. 명시적으로 main context로 옮겨야 모델이 본다.
     - **recall storage** — 모든 메시지를 영구 저장하는 메시지 DB.
     - **archival storage** — 임의 길이 텍스트를 저장하는 읽기/쓰기 DB. 실험에서는 PostgreSQL + pgvector.
3. **queue manager가 넘침을 다룬다.**
   - prompt가 **warning token count**(예: window의 70%)를 넘으면 "memory pressure" 시스템 메시지를 넣는다. 모델은 이 경고를 보고 중요한 정보를 working context나 archival storage에 저장한다.
   - **flush token count**(예: 100%)를 넘으면 메시지 일부(예: window의 50%)를 밀어내고, 기존 요약과 밀려난 메시지로 새 재귀 요약을 만든다.
   - 밀려난 메시지는 context에서 사라지지만 **recall storage에 무기한 남아** 함수로 다시 읽을 수 있다.
4. **memory 편집과 검색은 전부 모델이 스스로 한다(self-directed).** 언제 무엇을 옮길지 모델이 정한다. system instructions에 (1) memory 계층과 각각의 쓰임, (2) 자연어 설명이 붙은 function schema를 넣어 이를 유도한다. 함수 실행 결과와 **런타임 에러도 모델에게 되먹인다.** 저자들은 *"context 한계를 의식하는 것이 자기 편집이 작동하는 핵심"* 이라고 쓴다. 검색 결과는 페이지 단위로 나눠 context를 넘치지 않게 한다.
5. **이벤트가 추론을 트리거한다.** 사용자 메시지, 시스템 메시지(용량 경고), 사용자 행동(로그인, 문서 업로드 완료), **정해진 일정의 timed event**가 이벤트다. timed event 덕분에 사용자 개입 없이 "unprompted"로 돌 수 있다. 함수에 `request_heartbeat=true`를 주면 결과를 받은 즉시 다시 추론한다(function chaining). 플래그가 없으면 다음 외부 이벤트까지 멈춘다(yield).
6. **결과.**
   - **Deep Memory Retrieval (DMR, consistency).** Multi-Session Chat(MSC) 데이터셋의 5개 세션 뒤에 과거 대화로만 답할 수 있는 질문을 던진다. LLM judge 정확도:

     | 모델 | baseline | + MemGPT |
     |---|---|---|
     | GPT-3.5 Turbo | 38.7% | 66.9% |
     | GPT-4 | 32.1% | 92.5% |
     | GPT-4 Turbo | 35.3% | 93.4% |

     단, baseline은 원본 대화가 아니라 **지난 5개 세션의 손실 요약**을 받았다. MemGPT는 원본 전체를 페이지 단위 검색으로 볼 수 있었다.
   - **Conversation opener (engagement).** 과거 대화의 persona 정보를 반영한 첫 인사를 만든다. 사람이 쓴 opener와 비슷하거나 가끔 넘었다(SIM-1 0.830~0.868 vs 사람 0.800). working context에 정보를 저장하는 것이 핵심이었다.
   - **Multi-document QA.** NaturalQuestions-Open에서 50문항. 고정 context baseline은 retriever 성능이 상한이다. MemGPT는 archival storage를 여러 번 검색해 결과를 넘겨 볼 수 있어 문서 수가 늘어도 성능이 떨어지지 않았다. 다만 **retriever 결과를 끝까지 넘기기 전에 멈추는** 경향이 있었다.
   - **Nested KV retrieval (multi-hop).** 값이 다시 키인 UUID 쌍 140개(약 8k token)에서 nesting 0~4단계. GPT-3.5는 1단계에서 0%, GPT-4와 GPT-4 Turbo는 3단계에서 0%. **MemGPT+GPT-4만 단계가 늘어도 성능이 유지됐다.**
7. **성능이 하부 모델의 능력에 묶여 있다.**
   - GPT-3.5에서는 function calling 능력이 약해 문서 QA 성능이 크게 떨어졌다. GPT-4에서 가장 좋았다.
   - nested KV에서 **baseline으로는 GPT-4 Turbo가 GPT-4보다 낫지만, MemGPT에 올리면 GPT-4 Turbo가 GPT-4보다 나빴다.** 조회를 충분히 하지 않아 2단계부터 떨어졌다.

## Notable Quotes / Passages

> *"In MemGPT, we treat context windows as a constrained memory resource, and design a memory hiearchy for LLMs analogous to memory tiers used in traditional OSes."*

> *"Memory edits and retrieval are entirely self-directed: MemGPT autonomously updates and searches through its own memory based on the current context."*

> *"Awareness of context limits is a key aspect in making the self-editing mechanism work effectively, to this end MemGPT prompts the processor with warnings regarding token limitations to guide its memory management decisions."*

> *"Once the queue is flushed, the evicted messages are no longer in-context and immediately viewable to the LLM, however they are stored indefinitely in recall storage and readable via MemGPT function calls."*

LLM judge 프롬프트 (부록 6.1.2, 발췌):

> *"The generated answer might be much longer, but you should be generous with your grading - as long as it touches on the same topic as the gold answer, it should be counted as CORRECT."*

## My Notes

- **비교가 MemGPT 쪽에 유리하게 짜였다.** DMR baseline은 손실 요약만 받았다. 원본 대화 전체를 긴 context에 넣은 baseline은 없다. GPT-4 Turbo(128k)라면 MSC 5세션(세션당 약 12개 메시지)은 충분히 들어갔을 것이다. *(추론)*
  > **실측으로 확인됨 (2026-11-26).** [[2025-01-20-zep]]이 DMR을 다시 쟀다. 대화 전체를 context에 넣은 gpt-4-turbo baseline이 **94.4%** 로 MemGPT의 보고치(93.4%)보다 높았다. gpt-4o-mini에서는 98.0%였다. Zep 저자들은 DMR 대화가 60메시지라 context에 다 들어가고 단일 사실 질문뿐이어서 memory 시스템 평가에 부적합하다고 본다. 같은 저자들은 MemGPT를 gpt-4o-mini로 재현하려 했지만 방법 설명이 부족해 못 했다고 쓴다.
- **판정자가 관대하다.** "같은 주제를 건드리면 CORRECT"라는 기준이라 DMR 정확도는 상한에 가깝게 읽어야 한다. 문서 QA 표본은 50문항이다.
- **자기 데이터셋.** DMR, nested KV 과제와 DMR 질문 생성은 저자들이 만들었다. 질문은 별도 LLM이 생성했다.
- **2023년 모델만 실험했다.** 이후 모델에서 결론이 유지되는지는 이 소스로 알 수 없다. 특히 7번(새 모델이 오히려 나빴다)은 모델이 바뀌면 어느 방향으로든 달라질 수 있다.
- **이 위키와의 대응 *(추론)*.** 이 위키 자체가 MemGPT 구조와 닮았다. `CLAUDE.md`는 system instructions, `index.md`는 working context, `wiki/`는 archival storage, `log.md`는 recall storage에 가깝다. 차이는 누가 쓰는가다. MemGPT는 모델이 혼자 쓰고, 이 위키는 사람과 합의한 뒤 쓴다.
