# A-MEM: Agentic Memory for LLM Agents

> Zettelkasten 방식의 agent memory. 상호작용 하나를 **원자적인 노트**로 만들고, LLM이 노트끼리 **링크**를 걸고, 새 노트가 들어오면 가까운 기존 노트의 설명과 태그를 **다시 쓴다**(memory evolution). LoCoMo에서 여러 세션을 엮는 질문의 성능을 baseline의 2배 이상으로 올리고 token은 85~93% 줄였다. 단순 사실 질문에서는 GPT-4o 기준 baseline보다 낮았다.

## Key Claims

1. **문제 제기.** 기존 memory 시스템(MemGPT, MemoryBank, Mem0 등)은 개발자가 저장 구조, 저장 시점, 검색 시점을 **미리 정해 둬야** 한다. graph DB를 쓰는 Mem0도 스키마와 관계를 미리 정한다. 그래서 새로운 지식이 들어와도 정해진 틀 안에서만 분류하고 연결한다.
2. **노트 구성.** 노트 하나는 m_i = {c_i, t_i, K_i, G_i, X_i, e_i, L_i}다.
   - **c_i** 원본 상호작용 내용, **t_i** timestamp
   - **K_i** LLM이 만든 keyword, **G_i** LLM이 만든 tag, **X_i** LLM이 만든 contextual description
   - **e_i** 위 텍스트를 모두 이어 붙인 임베딩, **L_i** 링크된 노트들
   
   원문(c_i)에 LLM이 만든 설명을 덧붙여 임베딩하므로 검색 key가 원문보다 풍부해진다.
3. **link generation.** 새 노트의 임베딩으로 가장 가까운 기존 노트 k개를 찾고, LLM이 그중 무엇과 연결할지 정한다. 임베딩은 1차 필터이고, 인과·개념 관계 판단은 LLM이 한다. 노트는 여러 "box"(관련 노트 묶음)에 동시에 속할 수 있다.
4. **memory evolution.** 링크를 만든 뒤, 가까운 기존 노트 각각에 대해 LLM이 **context, keyword, tag를 갱신할지** 정한다. *"The evolved memory m_j\* then replaces the original memory m_j."* 갱신 대상은 LLM이 만든 속성들이고 원본 내용(c_i)은 아니다. 이전 버전을 남긴다는 설명은 없다. 갱신 프롬프트(부록 B)의 JSON 형식에는 "strengthen", **"merge", "prune"** 동작이 들어 있지만, 본문의 방법 설명과 실험은 연결 강화와 이웃 갱신만 다룬다.
5. **검색.** 질의 임베딩과 노트 임베딩의 cosine 유사도로 상위 k개(주로 10)를 가져온다. 가져온 노트와 같은 box에 링크된 노트도 함께 가져온다.
6. **LoCoMo 결과** (F1, 평균 9k token, 최대 35세션, 7,512 질문):

   | 모델 | 방식 | Multi-hop | Temporal | Open domain | Single-hop | Adversarial | 평균 token |
   |---|---|---|---|---|---|---|---|
   | GPT-4o-mini | LoCoMo | 25.02 | 18.41 | 12.04 | 40.36 | **69.23** | 16,910 |
   | | MemGPT | 26.65 | 25.52 | 9.15 | 41.04 | 43.29 | 16,977 |
   | | A-MEM | **27.02** | **45.85** | **12.14** | **44.65** | 50.03 | 2,520 |
   | GPT-4o | LoCoMo | 28.00 | 9.09 | 16.47 | **61.56** | **52.61** | 16,910 |
   | | MemGPT | 30.36 | 17.29 | 12.24 | 60.16 | 34.96 | 16,987 |
   | | A-MEM | **32.86** | **39.41** | **17.10** | 48.43 | 36.35 | 1,216 |

   (LoCoMo 행은 대화 전체를 context에 넣는 baseline이다.) 작은 오픈 모델(Qwen2.5, Llama 3.2)에서는 거의 모든 항목에서 A-MEM이 가장 높았다. **GPT 계열에서는 single-hop과 adversarial(답할 수 없는 질문 판별)에서 대화 전체를 넣은 baseline보다 낮았다.** 저자들은 이를 baseline이 *"단순 사실 검색에 강한 사전학습 지식"* 덕이라고 설명한다.
7. **DialSim** (TV 드라마 기반 다자 대화, 약 350k token): A-MEM F1 3.45, LoCoMo 2.55, MemGPT 1.18. 절대 수치가 모두 매우 낮다.
8. **ablation (GPT-4o-mini, LoCoMo F1).** 링크와 갱신을 둘 다 빼면 multi-hop 9.65, 갱신만 빼면 21.35, 전체 27.02. 링크가 기반이고 갱신이 추가로 다듬는다.
9. **비용.** memory 연산 하나에 약 1,200 token, 상용 API 기준 0.0003달러 미만. 처리 시간은 GPT-4o-mini로 평균 5.4초, 로컬 Llama 3.2 1B로 1.1초.
10. **Claude 결과 (부록 A.3, F1).**

    | 모델 | 방식 | Multi-hop | Temporal | Open domain | Single-hop | Adversarial |
    |---|---|---|---|---|---|---|
    | Claude 3.0 Haiku | LoCoMo | 4.56 | 0.82 | 2.86 | 3.56 | 3.46 |
    | | MemGPT | 7.65 | 1.65 | 7.41 | 8.60 | 7.66 |
    | | A-MEM | 19.28 | 16.65 | 11.85 | 34.72 | 35.99 |
    | Claude 3.5 Haiku | LoCoMo | 11.34 | 3.29 | 3.79 | 14.01 | 7.37 |
    | | MemGPT | 8.27 | 3.99 | 4.71 | 16.52 | 5.64 |
    | | A-MEM | 29.70 | 31.54 | 11.42 | 42.60 | 13.65 |

11. **저자들의 한계.** memory 조직의 품질이 하부 LLM 능력에 좌우된다. LLM마다 다른 설명을 만들고 다른 링크를 건다. 텍스트만 다룬다.

## Notable Quotes / Passages

> *"When a new memory is added, we generate a comprehensive note containing multiple structured attributes, including contextual descriptions, keywords, and tags. The system then analyzes historical memories to identify relevant connections, establishing links where meaningful similarities exist."*

> *"As new memories are integrated, they can trigger updates to the contextual representations and attributes of existing historical memories, allowing the memory network to continuously refine its understanding."*

> *"The evolved memory m_j\* then replaces the original memory m_j in the memory set M."*

> *"Although our system dynamically organizes memories, the quality of these organizations may still be influenced by the inherent capabilities of the underlying language models."*

## My Notes

- **Claude 데이터는 조심해서 읽는다.** Claude 3.0 Haiku에서 대화 전체를 넣은 baseline의 F1이 0.82~4.56으로 비정상적으로 낮다. 같은 baseline이 GPT-4o-mini에서는 12~69다. 프롬프트나 출력 형식이 Claude와 맞지 않았을 가능성이 있다. 원인은 논문에 설명이 없다. *(추론)*
- **지표가 F1과 BLEU-1이다.** 단어 겹침 지표라 답의 표현 방식에 민감하다. LongMemEval처럼 판정자를 쓰거나 사람과 대조하지 않았다.
- **GPT-4o에서의 single-hop 하락은 작지 않다** (61.56 → 48.43). top-k 검색이 단순 사실에 필요한 문맥을 빠뜨렸을 수 있다. 저자들의 설명(baseline의 사전학습 지식)은 baseline도 같은 모델이라는 점에서 설득력이 약하다. *(추론)*
- **덮어쓰기의 위험은 다루지 않는다.** LLM이 잘못 갱신하면 원래 속성은 남지 않는다. 원본 내용(c_i)은 남지만 검색은 갱신된 속성이 섞인 임베딩으로 하므로, 잘못된 갱신이 검색 결과를 바꿀 수 있다. *(추론)*
- **삭제는 프롬프트에만 있다.** "prune"이 갱신 프롬프트 JSON에 있지만 무엇을 언제 지우는지는 설명도 실험도 없다.
- **이 위키와의 대응 *(추론)*.** 새 노트가 들어오면 가까운 노트를 찾아 링크를 걸고 기존 노트를 갱신하는 흐름은 이 위키의 ingest(새 소스 → 영향받는 페이지 갱신 → cross-reference 추가)와 같다. 차이는 둘이다. 이 위키는 갱신 전에 **사람과 takeaway를 합의**하고, 바뀐 이력이 **git과 `log.md`에 남는다.** A-MEM에는 둘 다 없다.
