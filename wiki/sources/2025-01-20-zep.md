# Zep: A Temporal Knowledge Graph Architecture for Agent Memory

> agent memory를 **시간을 아는 knowledge graph**로 둔다. 원본 대화를 손실 없이 보존하고, 거기서 뽑은 사실마다 **언제부터 언제까지 참이었는지**를 기록한다. 새 사실이 옛 사실과 모순되면 옛 사실을 **지우지 않고 무효화**한다. LongMemEval에서 context 전체를 넣는 방식보다 정확도는 최대 18.5%(상대) 높고 지연은 약 90% 짧았다. **회사가 자사 제품을 소개하는 preprint**다.

## Context

- **저자:** 전원 Zep AI 소속 5명.
- **발행:** arXiv 2501.13956 v1, 2025-01-20. 동료 심사를 거치지 않았다. 12쪽(부록 포함).
- **성격:** Zep은 상용 memory 서비스이고, 핵심 엔진 Graphiti는 공개돼 있다. 이 논문은 그 제품의 구조와 벤치마크 결과를 소개한다. **벤더 자사 제품 편향**이 있다.
- **실험 모델:** graph 구축은 gpt-4o-mini, 답변 생성은 gpt-4o-mini와 gpt-4o, DMR 비교용으로 gpt-4-turbo. 임베딩과 reranker는 BGE-m3. Claude는 없다. 실험 시기는 2024년 12월~2025년 1월.
- **이 위키에서의 위치:** memory **갱신을 구현하는** 첫 소스. [[2023-10-12-memgpt]]의 DMR과 [[2024-10-14-longmemeval]]을 그대로 써서, 위키의 앞 소스들과 직접 비교된다. → [[anthropic]]

## Key Claims

1. **3층 graph.**
   - **Episode subgraph** — 원본 메시지, 텍스트, JSON. *"non-lossy data store"* 로, 여기서 entity와 관계를 뽑는다.
   - **Semantic entity subgraph** — 뽑은 entity(node)와 entity 사이의 사실(edge).
   - **Community subgraph** — 강하게 연결된 entity 묶음과 그 요약.
   
   원본(episodic)과 추출한 의미(semantic)를 함께 두는 것은 사람 기억의 episodic/semantic 구분을 따른 것이라고 설명한다. 사실(edge)과 원본(episode) 사이에 **양방향 색인**이 있어, 사실에서 출처로 거슬러 올라가 인용할 수 있다. 다만 이 기능은 이 논문의 실험에서 검증하지 않았다.
2. **bi-temporal 모델.** 시간 축이 둘이다. **T**는 사건이 실제로 일어난 순서, **T′**는 Zep이 데이터를 받아들인 순서다(감사용). 사실(edge)마다 시간 넷을 저장한다. **t_valid, t_invalid**(T, 사실이 참이었던 기간)와 **t′_created, t′_expired**(T′, 시스템에 들어오고 무효화된 시점)다. 메시지의 기준 시각(t_ref)을 써서 "2주 전에 새 직장을 시작했다" 같은 상대 시간도 절대 시각으로 바꾼다.
3. **edge invalidation — 지우지 않고 무효화한다.** 새 사실이 들어오면 LLM이 의미가 가까운 기존 사실과 비교해 모순을 찾는다. 시간이 겹치는 모순이 있으면, 옛 사실의 t_invalid를 새 사실의 t_valid로 설정한다. **새 정보가 우선한다**(T′ 기준). 그래서 graph는 *"현재 관계 상태와 관계가 변해 온 역사 기록을 둘 다"* 유지한다.
4. **추출 과정.**
   - entity 추출은 현재 메시지와 직전 4개 메시지를 함께 본다. 추출 뒤 **Reflexion에서 영감을 받은 반성 단계**로 hallucination을 줄이고 누락을 채운다.
   - 같은 entity가 이미 있는지 임베딩 검색 + full-text 검색 + LLM 판정으로 확인해 합친다(entity resolution). 사실(edge)도 같은 entity 쌍 사이에서만 중복을 찾는다.
   - graph에 넣을 때는 LLM이 생성한 DB 질의 대신 **미리 정해 둔 Cypher 질의**를 쓴다. 스키마를 일관되게 지키고 hallucination을 줄이려는 선택이다.
   - community는 label propagation으로 묶고, 새 entity가 들어오면 이웃 다수의 community에 붙인다. 이 방식은 점점 정확한 결과에서 멀어지므로 **주기적인 전체 재계산**이 필요하다.
5. **검색.** 세 검색(cosine 유사도, BM25 full-text, graph 위의 breadth-first search)으로 후보를 모으고, reranker(RRF, MMR, 언급 빈도, graph 거리, cross-encoder)로 고른 뒤, 사실과 **유효 기간**, entity 요약을 텍스트 context로 만든다.
6. **DMR 결과와 DMR 비판.**

   | memory 방식 | 모델 | 점수 |
   |---|---|---|
   | 재귀 요약 | gpt-4-turbo | 35.3% |
   | 대화 요약 | gpt-4-turbo | 78.6% |
   | MemGPT (MemGPT 논문 수치) | gpt-4-turbo | 93.4% |
   | **대화 전체를 context에** | gpt-4-turbo | **94.4%** |
   | Zep | gpt-4-turbo | 94.8% |
   | 대화 요약 | gpt-4o-mini | 88.0% |
   | 대화 전체를 context에 | gpt-4o-mini | 98.0% |
   | Zep | gpt-4o-mini | 98.2% |

   **대화 전체를 그대로 넣은 baseline이 MemGPT보다 높았다.** 저자들은 DMR 대화가 60메시지라 context에 다 들어가고, 단일 사실 질문뿐이며, 질문 문구가 모호하다며 *"memory 시스템 평가에 부적합하다"* 고 본다. MemGPT의 결과를 gpt-4o-mini로 재현하려 했지만 방법 설명이 부족해 못 했다.
7. **LongMemEval 결과** (LongMemEval_S, 평균 115k token, 판정자 GPT-4o와 LongMemEval의 유형별 프롬프트):

   | 방식 | 모델 | 정확도 | 지연(중앙) | 평균 context |
   |---|---|---|---|---|
   | context 전체 | gpt-4o-mini | 55.4% | 31.3s | 115k |
   | Zep | gpt-4o-mini | 63.8% | 3.20s | 1.6k |
   | context 전체 | gpt-4o | 60.2% | 28.9s | 115k |
   | Zep | gpt-4o | 71.2% | 2.58s | 1.6k |

   - 18.5%와 15.2%는 **상대** 개선이다(60.2 → 71.2).
   - 유형별로 보면 preference, 여러 세션, 시간 추론에서 크게 올랐다. **assistant가 한 말을 기억하는 문제는 떨어졌다**(gpt-4o −17.7%, gpt-4o-mini −9.06%).
   - **knowledge update는 gpt-4o에서만 올랐다**(+6.52%). gpt-4o-mini에서는 떨어졌다(−3.36%). 저자들은 *"덜 강한 모델이 Zep의 시간 데이터를 이해하려면 더 개발이 필요하다"* 고 쓴다.
   - abstention 유형은 이 표에 없다(여섯 유형만 보고).
   - Zep은 AWS에 두고 보스턴의 가정용 노트북에서 접속해 쟀다. 네트워크 지연은 Zep 쪽에만 들어갔다.
   - **MemGPT도 LongMemEval로 재려 했지만** 기존 대화를 넣을 방법이 없어 archival에 넣는 우회를 썼고, 답을 얻지 못했다.
8. **저자들의 문제 제기.** 적절한 memory 벤치마크가 드물다. 대화와 **구조화된 업무 데이터**를 함께 다루는 능력을 재는 벤치마크는 없다. memory 연구는 비용과 지연을 충분히 다루지 않는다.

## Notable Quotes / Passages

> *"The Graphiti KG engine dynamically updates the knowledge graph with new information in a non-lossy manner, maintaining a timeline of facts and relationships, including their periods of validity."*

> *"When the system identifies temporally overlapping contradictions, it invalidates the affected edges by setting their t_invalid to the t_valid of the invalidating edge."*

> *"The high performance achieved by simple full-context approaches using modern LLMs further highlights the benchmark's inadequacy for evaluating memory systems."*

## My Notes

- **자사 제품 논문이다.** 비교 대상 선택, 벤치마크 유형 보고 범위(abstention 제외), 지연 측정 조건을 모두 저자가 정했다. 다른 회사들(Mem0, Letta)이 서로 다른 수치를 내세운다는 점도 기억해 둔다.
- **무효화가 정확도에 기여한 몫은 따로 재지 않았다.** knowledge update 유형의 개선(gpt-4o +6.52%)이 bi-temporal 구조 덕인지, 다른 검색 요소 덕인지 ablation이 없다. *(추론)*
- **모순 판정도 LLM이 한다.** 무효화는 "LLM이 모순이라고 본 것"에만 일어난다. 판정이 틀리면 맞는 사실이 무효화되거나 틀린 사실이 남는다. 이 판정의 정확도는 보고되지 않았다. *(추론)*
- **DMR 비판은 위키의 MemGPT 노트를 확인해 준다.** [[2023-10-12-memgpt]] My Notes에 *(추론)* 으로 적은 "원본 대화 전체를 긴 context에 넣은 baseline이 없다"가 실측으로 확인됐다.
- **이 위키와의 대응 *(추론)*.** "모순이면 옛 사실을 지우지 않고 무효 표시, 새 정보 우선, 출처로 거슬러 올라갈 수 있음"은 이 위키 CLAUDE.md의 모순 처리 원칙(양쪽 보존, `⚠️ Contradiction`, `sources:`)과 같은 처방이다. 차이는 Zep이 **새 정보를 자동으로 우선**한다는 점이다. 이 위키는 어느 쪽이 맞는지 판정을 사람에게 남긴다.
