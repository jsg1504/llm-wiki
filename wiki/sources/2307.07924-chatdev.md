# ChatDev: Communicative Agents for Software Development

> 워터폴 모델을 "chat chain"이라는 dialogue 그래프로 재구성한 LLM 멀티에이전트 소프트웨어 개발 프레임워크. 이중 에이전트(Instructor/Assistant) 다중 턴 대화 + communicative dehallucination + 이중 메모리. 자체 SRDD 벤치에서 GPT-Engineer / [[metagpt]] 대비 우위를 주장.

## Context

- **저자**: Chen Qian (Tsinghua, 1저자), Maosong Sun (Tsinghua, 교신). Tsinghua + ModelBest Inc + USyd + BUPT 공동.
- **발표**: arXiv v5 = 2024-06-05 (단일 컬럼 본문 형식상 ACL 2024 main 추정 — 단언하지 않음).
- **배경**: 2023년 멀티에이전트 LLM 시스템들(MetaGPT, AgentVerse, AutoGPT) 흐름에 합류. 차별점은 "워터폴 phase를 dialogue 자체로 모델링"이라는 통신 중심 설계.
- **공개**: github.com/OpenBMB/ChatDev.

## Key Claims

1. **Chat Chain 𝓒 = ⟨𝓟¹, 𝓟², …⟩** — 워터폴의 phase들을 sequential 대화 그래프로 표현. 각 phase 𝓟는 subtask 𝓣들로, 각 subtask는 **이중 에이전트 (Instructor 𝓘 + Assistant 𝓐)** 다중 턴 dialogue로 풀린다. 형식: `𝓣 = τ(𝓒(𝓘, 𝓐))`, `𝓒(𝓘, 𝓐) = ⟨𝓘 → 𝓐, 𝓐 ⤳ 𝓘⟩↻`. 5개 역할: CEO, CTO, programmer, reviewer, tester. 3 phase: Design / Coding (코딩 + code complete) / Testing (code review + system testing).

2. **Communicative Dehallucination (CDH)** — coding hallucination을 "역할 반전"으로 잡는다. 일반 패턴이 instructor가 묻고 assistant가 답하는 것이라면, CDH는 assistant가 먼저 instructor에게 더 구체적인 정보를 요구한 뒤 답하는 패턴: `⟨𝓘 → 𝓐, ⟨𝓐 → 𝓘, 𝓘 ⤳ 𝓐⟩↻, 𝓐 ⤳ 𝓘⟩↻`. ablation에서 CDH 제거 시 4개 metric 모두 하락.

3. **이중 메모리 = Short-term + Long-term.** Short-term은 phase 내 utterance 누적(`𝓜ᵢ_t = ⟨(𝓘ᵢ₁, 𝓐ᵢ₁), …⟩`), Long-term은 phase 간 *솔루션만* 전달(전체 history는 아님). 의도: context 폭증 차단 + 정보 과부하 차단. → [[metagpt]]가 같은 문제를 publish-subscribe + role 기반 subscription으로 푼 것과 대비.

4. **Inception Prompting.** Instructor/Assistant 양쪽에 거의 대칭적인 system prompt(P_I, P_A)를 주입: 현 subtask의 overview·objective, 역할, 사용 가능한 외부 도구, 통신 프로토콜, 종료 조건, 안티 행동 제약. `𝓘 = ρ(LLM, P_I)`, `𝓐 = ρ(LLM, P_A)`.

5. **자체 SRDD 벤치 (1,200 task) + 4 metric.**
   - Completeness — placeholder 코드 비율의 역수.
   - Executability — 컴파일·실행 성공률.
   - Consistency — 요구 텍스트 ↔ 생성 코드 임베딩의 cosine similarity.
   - Quality — 위 셋의 곱.
   - SRDD: 1,200 prompt, 5 카테고리 (Education/Work/Life/Game/Creation), 40 subcategory.
   - 평가 모델: ChatGPT-3.5, temperature 0.2, Python 3.11.4.

6. **결과 (자체 벤치 기준):**
   - Quality: ChatDev **0.3953** > MetaGPT 0.1523 > GPT-Engineer 0.1419
   - Executability: ChatDev **0.8800** > MetaGPT 0.4145 > GPT-Engineer 0.3583
   - Pairwise (GPT-4 / human evaluator): ChatDev wins 77~90% vs GPT-Engineer, 57~88% vs MetaGPT.

## ⚠️ Contradiction with [[2308.00352-metagpt]]

> **양 논문이 자기네 자체 벤치에서 서로를 이긴다고 주장한다.**

| 출처 | 벤치 | ChatDev | MetaGPT |
|---|---|---|---|
| [[2308.00352-metagpt]] (MetaGPT 논문, SoftwareDev 70-task) | Executability /4 | 2.25 | **3.75** |
| [[2307.07924-chatdev]] (ChatDev 논문, SRDD 1,200-task) | Executability ∈[0,1] | **0.8800** | 0.4145 |

토큰 사용량도 보고치 다름:
- MetaGPT 논문: ChatDev 19,292 / MetaGPT 31,255
- ChatDev 논문: ChatDev 22,949 / MetaGPT 29,278

모순의 가능한 원인 (확정 아님):
- 서로 다른 벤치(SoftwareDev vs SRDD), 서로 다른 평가 metric, 서로 다른 task 분포.
- 각자 자기 방법에 친화적인 task를 골랐을 가능성 (selection bias).
- 토큰 측정 시점/조건 차이 (one-shot vs full pipeline 등 명세 안 함).

**위키 포지션**: 자체 벤치 cross-citation은 일반적으로 신뢰 약함. 어느 한쪽이 옳다고 결론 내리지 않음. 독립적 third-party 벤치(예: HumanEval/MBPP) 결과만 cross-validate에 쓰는 게 안전.

## Notable Quotes

> "ChatDev includes a *communicative dehallucination* mechanism, wherein agents request more detailed information before responding directly and then continue the next round of communication based on these details." (§1)

> "By sharing only the solutions of each subtask rather than the entire communication history, ChatDev minimizes the risk of being overwhelmed by too much information…" (§3.1, Memory)

> "MetaGPT … incorporates standardized operating procedures to enable multi-agent participation. In each step agents with specific roles generate solutions by adhering to **static instructions predefined by human experts**." (§2, Related Work — ChatDev 측 MetaGPT 평가)

## My Notes

- ChatDev은 자기 정체성을 "communicative" 쪽에 둔다. MetaGPT가 "structured documents"로 통신 잡음을 줄이려 한다면, ChatDev은 "더 깊은 dialogue"로 그 잡음을 풀려 한다 — 정반대 디자인 철학.
- §2에서 MetaGPT를 "**static** instructions predefined by human experts"라 평가한 부분은 의도적 평가절하로 읽힘. SOP가 정적이라는 비판은 fair하지만, MetaGPT의 executable feedback loop은 정적이라 보기 어려움.
- 자체 벤치 + 자체 metric만으로 비교하면 거의 항상 자기네가 이긴다 — 학계의 알려진 문제. 이 위키에서는 **자체 벤치 비교는 약한 증거**라는 메타 원칙을 둘 가치가 있어 보임.
- Communicative Dehallucination의 "역할 반전"은 실용적이고 단순한 트릭. 이름은 거창하지만 본질은 "assistant가 unclear 요구사항이면 먼저 clarify 요청하라"는 프롬프트 패턴.
- 자체 한계 인정 부분(§6)에서 "벤치마크가 prototype 수준 task에 적합하고 real-world complex app엔 부족"하다고 솔직히 적은 점은 honest.
